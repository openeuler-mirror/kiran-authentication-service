# Feature Specification: 本地人脸识别认证

**Feature Branch**: `001-face-recognition`

**Created**: 2026-08-18

**Status**: Draft

**Input**: User description: "为 kiran-authentication-service 增加本地人脸识别认证功能(注意:不是 ks-authhub 那套方案,不参考它)。核心:在本地直接进行人脸识别操作,基本算法代码参考 /mnt/1t/y/opencv/backport_452/ncnn_test.cpp。需要支持人脸录入:录入操作在 /mnt/1t/y/kiran-control-panel 中进行,由 /mnt/1t/y/kiran-authentication-service/src/device/adaptor/device.h 提供接口给 kiran-control-panel 调用,进行人脸特征的录入与管理"

## Clarifications

### Session 2026-08-18

- Q: 摄像头画面中出现多张人脸时,录入和识别应如何处理? → A: 均取面积最大的一张人脸进行处理(2026-08-19 两次修正:原答为两者均拒绝;后改为认证取最大脸;最终录入也统一为取最大脸,取消多脸拒绝)
- Q: 每个操作系统账户最多允许录入几个人脸特征?"用户"是操作系统用户概念吗? → A: "用户"即操作系统账户,root 与普通用户规则一致(2026-08-19 修正:原答"不设硬上限",后经与现有 daemon 代码核对,存在 FEATURE_COUNT_MAXIMUN=10 的强制检查,改为保留每账户 10 个上限)
- Q: SC-001 的"3 秒内返回识别结果"以什么硬件作为验收基准? → A: 不设统一时限,以不拖垮现有 PAM 认证链路为准
- Q: 录入时什么时候显示预览画面? → A: 依据现有 kiran-control-panel 录入流程确定:管理页点"录入"并通过密码验证 → 切入录入页即开摄像头预览(替换原 272×272 静态进度图位置,新增"拍照/录入"按钮)→ 点击拍照时捕获当前帧并随录入请求一起提交给服务(复用现有 EnrollStatus 进度反馈)→ 完成/失败回管理页;取消或关页即关摄像头(处理中则先停止录入);预览停留 2 分钟无操作自动关闭并回管理页
- Q: 人脸录入/识别的操作语义参考旧代码的哪一部分? → A: 参考 kiran-authentication-devices 的 multi-function(IriStar 虹膜+人脸)设备模式:录入时先取已录入特征检测重复 → 采集 → 特征ID=特征数据哈希 → 存入本地特征库(FeatureDB)→ 按流程上报状态(采集失败可重试/重复录入拒绝/保存成功完成);识别时加载目标用户的已录入特征列表进行比对,匹配返回特征ID。面板→服务的图像传输在本架构下是新环节(旧架构摄像头在服务侧),采用图像 base64 放入 extraInfo JSON 随录入请求一并传递,不新增 D-Bus 方法;录入会话在点击拍照时建立
- Q: 本地人脸识别与现有"软人脸(soft face)"是什么关系? → A: 命名上必须区分:现有 SoftFaceDriver/软人脸(KAD_AUTH_TYPE_SOFT_FACE)专指人脸比对在远端服务器执行的 ks-authhub 方案;本需求是本地直接识别,对应既有枚举中的 KAD_AUTH_TYPE_FACE / DEVICE_TYPE_FACE,新设备与驱动不得沿用 "soft/软" 命名
- Q: 锁屏/登录界面的人脸识别,持续尝试采集多久后自动超时结束? → A: 默认 10 秒,快速失败让用户尽快切换其他认证方式;超时提示"识别超时"并结束本次识别
- Q: 识别结果不匹配(非本人脸)后,本次识别流程是自动继续扫描还是结束? → A: 结束本次识别:返回不匹配结果并提示,由用户重新发起或切换其他认证方式(2026-08-19 修正:实测单帧相似度波动大[0.25~0.77],一帧定生死导致频繁失败;改为超时窗口内持续采集比对,不匹配继续采下一帧,窗口超时结束;开摄像头后跳 3 帧等曝光稳定)
- Q: 本次需求是否包含"人走监测"(用户离开后检测不到人脸自动锁屏)? → A: 不包含:本期只做录入/管理/识别认证,人走监测后续独立迭代
- Q: 锁屏"用户可切换"模式下 daemon 不传目标用户(空 feature_ids),人脸识别怎么办? → A: 设备空列表全库兜底:从本地特征库读全库特征比对,返回命中特征 ID,daemon 既有 matchUser 链路负责用户反查与合法性校验(2026-08-19 裁决,FR-012 同步修订)

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 控制面板人脸录入 (Priority: P1)

用户在控制面板的"身份认证 → 人脸"页面点击录入并通过密码验证后,进入录入页;录入页立即打开摄像头实时预览,用户对准摄像头后点击"拍照/录入"按钮,面板将当前画面图像传给认证服务,服务完成人脸检测、特征提取与保存并回报进度和结果;完成后新的人脸特征出现在特征列表中,并立即可用于登录认证。失败或取消时给出明确提示且不留无效数据。

**Why this priority**: 录入是使用人脸认证的前提——没有已录入特征,识别认证无从谈起,因此是最先要打通的主链路。

**Independent Test**: 在一台带摄像头的终端上,登录桌面系统后打开控制面板人脸页,点击"录入"、在预览中确认人脸后点击"拍照/录入"按钮,可独立验证从预览、采图传图、进度反馈、特征保存到列表展示的完整闭环,无需其他功能配合。

**Acceptance Scenarios**:

1. **Given** 用户已登录且面板可打开摄像头, **When** 在人脸页点击录入并通过密码验证, **Then** 面板切换到录入页,录入页立即显示摄像头实时预览
2. **Given** 预览画面中出现了人脸, **When** 用户点击"拍照/录入"按钮, **Then** 面板捕获当前画面,将图像随录入请求一并提交给认证服务,服务开始处理并回报进度
3. **Given** 服务收到的图像中检测到质量合格的人脸, **When** 特征提取并保存完成, **Then** 进度到达 100%,特征以"ID + 名称"形式出现在特征列表,该特征立即可参与认证
4. **Given** 图像中未检测到人脸或人脸质量不足, **When** 服务处理失败, **Then** 面板提示具体原因(如"未检测到人脸"),继续保留预览可直接重试,不产生残留特征
5. **Given** 录入进行中, **When** 用户点击取消或关闭页面, **Then** 流程终止、关闭摄像头、不保存特征,设备恢复空闲可再次使用
6. **Given** 录入页停留在预览状态, **When** 超过 2 分钟未进行任何操作, **Then** 面板自动关闭摄像头并返回特征管理页

---

### User Story 2 - 登录/锁屏人脸识别认证 (Priority: P1)

用户在登录、锁屏解锁等系统认证场景选择人脸认证方式,面对摄像头,系统在本地完成人脸识别比对,本人则认证通过,非本人则拒绝并提示。

**Why this priority**: 人脸识别认证是本功能的最终价值所在——录入与管理的全部目的都是支撑认证通过。

**Independent Test**: 在已录入人脸特征的环境下,锁屏后选择人脸认证,面对摄像头即可独立验证:本人通过、他人拒绝、停止后丢弃结果。

**Acceptance Scenarios**:

1. **Given** 当前用户已录入人脸特征, **When** 发起人脸认证且摄像头前为本人, **Then** 认证通过
2. **Given** 当前用户已录入人脸特征, **When** 摄像头前为非本人, **Then** 认证被拒绝并提示不匹配
3. **Given** 人脸设备正忙(录入或识别进行中), **When** 发起新的认证请求, **Then** 请求被明确拒绝并返回"设备忙"提示,用户可切换其他认证方式
4. **Given** 认证流程进行中, **When** 用户停止认证(如切换回密码), **Then** 进行中的识别结果被丢弃,不影响界面切换

---

### User Story 3 - 人脸特征管理 (Priority: P2)

用户在人脸页面查看已录入的人脸特征列表,可以对特征进行重命名和删除;删除后的特征不再参与认证。所有管理操作即时生效,且服务重启后仍然保持。

**Why this priority**: 特征管理是录入之后的日常使用需求,但不阻塞"录入 → 认证"的主链路,因此排在 P2。

**Independent Test**: 在已有录入特征的环境下,打开控制面板人脸页,可独立完成列表查看、重命名、删除并验证重启后状态保持。

**Acceptance Scenarios**:

1. **Given** 当前用户已有录入特征, **When** 打开人脸页, **Then** 列表展示全部已录入特征(名称及设备信息)
2. **Given** 选中某个特征, **When** 执行重命名, **Then** 新名称立即生效,且服务重启后仍为新名称
3. **Given** 选中某个特征, **When** 执行删除, **Then** 特征从列表移除,且此后该特征不再参与认证

---

### Edge Cases

- 无摄像头或摄像头被其他应用占用时发起录入/识别
- 面板打开摄像头失败、预览中断
- 面板传给服务的图像无效、损坏或传输失败
- 摄像头画面中同时出现多张人脸:录入与认证均取面积最大的一张人脸进行处理
- 光线不足、人脸过小、角度过大等低质量场景
- 特征库为空(未录入)时发起人脸认证
- 录入与识别并发:设备忙时的请求拒绝语义
- 录入进行中服务异常退出或面板崩溃断连:流程自动终止、不残留半成品数据
- 未录入人脸的用户尝试使用人脸认证
- 重复录入同一张人脸:拒绝保存并提示"该特征已录入"
- 照片、屏幕画面等非活体来源可被识别通过(本期不做活体检测,属已知限制,记录于假设)
- 人脸特征数据在本机的长期存储与容量增长(每账户上限 10 个;存储空间耗尽时录入失败并提示)
- 特征数达到上限后再次发起录入:拒绝并提示"特征数量已达上限"

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 人脸检测、特征提取与比对必须全部在本机完成,不依赖网络或任何远端服务
- **FR-002**: 认证服务必须通过设备接口向控制面板提供录入能力(启动/停止,并接收面板传入的人脸图像),录入过程中持续上报进度、状态与结果(成功时返回特征 ID)
- **FR-003**: 录入成功的人脸特征必须持久化保存在本机,服务重启后仍可查询和参与认证
- **FR-004**: 认证服务必须提供特征查询接口,返回当前用户已录入的特征列表(特征 ID、名称等)
- **FR-005**: 认证服务必须提供特征重命名与删除接口,操作即时生效并持久化
- **FR-006**: 认证服务必须提供识别接口,返回匹配、不匹配或失败及可理解的原因;识别在超时窗口(默认 10 秒)内持续采集比对,单帧不匹配不结束流程;窗口结束后区分结果:比对过人脸但均不匹配 → 提示"人脸不匹配";未检测到可比对人脸 → 提示"识别超时";由用户重新发起或切换其他认证方式
- **FR-007**: 设备处于录入/识别进行中时,新的录入或识别请求必须被明确拒绝并给出"设备忙"提示
- **FR-008**: 识别停止请求发出后,进行中的识别结果必须被丢弃,不得误报认证结果
- **FR-009**: 未检测到人脸、人脸质量不足、超时等失败场景必须给出明确、可理解的提示
- **FR-010**: 人脸识别比对必须使用可配置的相似度阈值,默认值保证他人误通过率达标
- **FR-011**: 本期范围不包含活体检测:录入与识别仅基于单帧静态图像的人脸检测与特征比对,不验证是否为活体(照片/屏幕攻击防护留待后续迭代)
- **FR-012**: 识别认证在 daemon 指定目标用户(特征 ID 列表非空)时,仅与该用户的已录入特征比对;在可切换锁屏场景(特征 ID 列表为空)下,与本地全库人脸特征比对并返回命中的特征 ID,由 daemon 既有链路反查用户并校验合法性
- **FR-013**: 录入采图由控制面板完成:面板实时预览摄像头画面,用户点击录入按钮后由面板将当前帧图像(JPEG base64 编码,放入录入请求的附加信息 JSON)提交给认证服务处理;录入阶段认证服务不主动打开摄像头采集
- **FR-016**: 录入页的预览显示时机为:切入录入页后立即开启摄像头预览;处理完成、失败、取消或页面关闭时必须关闭摄像头
- **FR-017**: 录入页停留在预览状态超过 2 分钟无操作时,必须自动关闭摄像头并返回特征管理页(若此时录入正在处理,先停止录入)
- **FR-018**: 录入时必须检测重复:新录入特征与当前用户已有特征重复时,拒绝保存并提示"该特征已录入"
- **FR-019**: 识别过程中未采集到人脸或特征质量不足时,系统应提示用户调整并持续尝试,直至匹配、用户停止或超时;默认超时时限为 10 秒,超时提示"识别超时"并结束本次识别
- **FR-020**: 本期范围不包含人走监测(检测不到人脸自动锁屏);识别设备仅支持"一次识别返回一个结果"的交互模式
- **FR-014**: 录入与认证画面中同时出现多张人脸时,均取面积最大的一张人脸进行处理
- **FR-015**: 每个操作系统账户最多可录入 10 个人脸特征(与现有认证服务对生物特征的数量限制一致);达到上限后发起录入时必须拒绝并明确提示

### Key Entities *(include if feature involves data)*

- **人脸特征 (Face Feature)**: 代表一次成功录入的人脸模板;关键属性:特征 ID(由特征数据唯一确定,重复录入相同人脸得到相同 ID)、内部标识(iid)、特征名称、所属用户、特征数据(比对的依据)、关联设备信息
- **人脸设备 (Face Device)**: 抽象本机本地人脸识别能力的载体;关键属性:设备 ID、状态(空闲/录入中/识别中)、驱动名称;一次只处理一个录入或识别流程(注意:区别于"软人脸",后者专指人脸比对在远端服务器执行的方案,不在本需求范围)
- **认证请求 (Auth Request)**: 代表一次认证会话;关键属性:发起用户、认证方式、附加信息、结果状态

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 人脸识别认证不得阻塞现有 PAM 认证链路:识别进行中用户可随时切换其他认证方式或停止,切换响应与现有体验一致;识别耗时以目标平台实测为基线记录在交付文档中
- **SC-002**: 本人识别通过率不低于 95%(本人连续 20 次尝试,通过不少于 19 次)
- **SC-003**: 他人误通过率不高于 0.1%(非本人尝试 1000 次,误通过不超过 1 次)
- **SC-004**: 首次录入成功率不低于 90%(正常使用条件下 20 次录入,成功不少于 18 次)
- **SC-005**: 特征的增、删、改、查操作完成后即时生效,无需重启服务
- **SC-006**: 断开网络后,录入、管理与识别全流程仍可正常工作

## Assumptions

- 摄像头控制权划分:录入阶段由控制面板控制摄像头(实时预览、点击采图、传图给服务);识别认证阶段(登录/锁屏)没有面板参与,由认证服务自行控制摄像头采集
- 控制面板需配套新增/改造录入预览页面(跨仓库改动,属于 kiran-control-panel 的配套变更,与本仓库改动一同交付)
- 算法方案与参考实现一致:人脸检测 → 特征提取 → 余弦相似度比对;参考实现基准为同一人相似度约 0.885、不同人约 0.179,默认阈值可在此区间选取
- 算法模型文件随软件包分发,安装后离线可用,无需联网下载
- 人脸特征存储在本机受保护目录,仅认证服务进程可读写,外部只能通过服务接口访问
- 用户在控制面板中管理的是自己的特征,操作无需管理员权限(与现有面板交互一致)
- 目标运行环境为带摄像头的国产化桌面终端,CPU 推理即可满足性能要求,无 GPU 依赖
- 认证场景沿用现有 PAM/会话认证链路,人脸作为其中一种可选认证方式;录入与管理复用现有控制面板"身份认证"模块的人脸页面
- 本期明确不做活体检测:照片/屏幕攻击防护作为后续迭代项,交付时需在文档中说明该安全边界
