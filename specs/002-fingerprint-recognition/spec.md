# Feature Specification: 本地指纹识别认证

**Feature Branch**: `002-fingerprint-recognition`

**Created**: 2026-09-01

**Status**: Implemented (as-built，按当前实现回写，供 spec-kit 后续迭代)

**Input**: 为 kiran-authentication-service 增加基于 libfprint 的本地指纹录入与识别认证。设备侧通过 USB 指纹采集器完成多阶段按压录入与一次扫描识别；控制面板沿用既有「身份认证 → 指纹」页面管理特征；登录/锁屏经 PAM → daemon → 设备管理服务完成识别。不走远端比对方案。

## Clarifications

### Session 2026-09-01（对照实现裁决）

- Q: 指纹设备从哪里来？ → A: USB 热插拔。驱动 `getSupportVidPid()` 优先解析 libfprint hwdb；设备管理进程按 VID/PID 创建设备对象并 `open`。无硬件时不暴露可用指纹设备。
- Q: 录入由谁采图？ → A: 服务侧指纹仪采集（多阶段按压）。面板只展示进度图与提示，不打开摄像头、不传图像。
- Q: 重复录入如何判定？ → A: 正式录入前，用当前用户已有特征做一次识别；命中则拒绝并提示「该指纹已录入」。查重范围仅当前用户（daemon 在 extraInfo 注入该用户 `feature_ids`），不做全库，避免误伤其他用户。
- Q: 识别比对范围？ → A: 不可切换用户：仅比对 daemon 注入的 `feature_ids`。可切换用户：`feature_ids` 为空，设备按 `user_name` 优先加载该用户特征，再追加全库其余特征；命中后由 daemon `matchUser` 反查并决定登录用户。
- Q: 识别是持续窗口还是单次扫描？ → A: 单次扫描结束即出 MATCH/NOT_MATCH（或错误）。匹配成功时驱动 early-cancel，避免一直等到抬起手指才返回；质量问题可通过 RETRY 提示继续尝试，直至本次扫描结束。
- Q: 每账户特征上限？ → A: 沿用 daemon `FEATURE_COUNT_MAXIMUN=10`，与人脸等生物特征一致。
- Q: 缺 libfprint 时构建？ → A: `BUILD_FINGERPRINT_DRIVER` 默认 ON；找不到 `libfprint-2`/`libfprint` 时跳过插件并 WARNING，不影响 pam/daemon 等核心组件构建。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 控制面板指纹录入 (Priority: P1)

用户在控制面板「身份认证 → 指纹」页点击录入并通过密码验证后进入录入页；按界面提示在指纹仪上多次按压，服务完成重复检测、多阶段采集、特征保存并回报进度；完成后新特征出现在列表，可立即用于登录/锁屏认证。失败、重复或取消时给出明确提示且不留无效数据。

**Why this priority**: 无录入特征则无法认证，是主链路前提。

**Independent Test**: 插入受支持的指纹仪，打开控制面板指纹页完成一次录入，验证进度、列表展示与失败/取消语义，无需锁屏配合。

**Acceptance Scenarios**:

1. **Given** 指纹仪已连接且驱动已加载, **When** 用户在指纹页点击录入并通过密码验证, **Then** 进入录入页并提示按压手指
2. **Given** 当前用户已有指纹特征, **When** 录入开始, **Then** 先提示重复检测按压；若与已有特征匹配, **Then** 拒绝录入并提示「该指纹已录入」，不进入正式录入
3. **Given** 重复检测通过（或尚无已有特征）, **When** 用户按提示完成多阶段按压, **Then** 进度递增至 100%，特征以「ID + 名称」出现在列表，可立即参与认证
4. **Given** 扫描质量不佳, **When** 驱动上报重试, **Then** 面板提示质量相关文案，用户可继续按压，不产生残留特征
5. **Given** 录入进行中, **When** 用户取消或关闭页面, **Then** 流程终止、不保存特征，设备恢复空闲
6. **Given** 当前用户特征数已达上限（10）, **When** 再次发起录入, **Then** 被拒绝并提示数量上限相关错误

---

### User Story 2 - 登录/锁屏指纹识别认证 (Priority: P1)

用户在登录、锁屏解锁等场景选择指纹认证，在指纹仪上按压；本人（或可切换模式下匹配到其他合法用户特征）则认证通过，否则拒绝并提示。

**Why this priority**: 识别认证是本功能最终价值。

**Independent Test**: 已录入特征后锁屏选指纹：本人通过、他人/错误手指拒绝、切换密码时停止无阻塞；可切换用户场景下用其他用户手指可切换登录。

**Acceptance Scenarios**:

1. **Given** 当前用户已录入指纹且不可切换用户, **When** 用本人手指识别, **Then** 认证通过
2. **Given** 当前用户已录入指纹且不可切换用户, **When** 用未登记或其他用户手指识别, **Then** 认证失败并提示
3. **Given** 锁屏允许切换用户且已输入用户 A, **When** 使用仅登记在用户 B 下的手指, **Then** 全库可命中 B 的特征，认证成功并以用户 B 登录
4. **Given** 锁屏允许切换用户且已输入用户 A, **When** 用户 A 与用户 B 对同一手指均有模板, **Then** 优先匹配用户 A 的特征
5. **Given** 指纹设备正忙, **When** 发起新的录入/识别, **Then** 明确拒绝并提示「设备忙」
6. **Given** 识别进行中, **When** 用户停止或切换其他认证方式, **Then** 进行中结果被丢弃，不误报成功

---

### User Story 3 - 指纹特征管理 (Priority: P2)

用户在指纹页查看已录入特征，可重命名与删除；删除后不再参与认证；服务重启后状态保持。

**Why this priority**: 日常管理需求，不阻塞「录入 → 认证」主链路。

**Independent Test**: 已有特征时独立完成列表、重命名、删除及重启后保持验证。

**Acceptance Scenarios**:

1. **Given** 已有录入特征, **When** 打开指纹页, **Then** 列表展示全部特征（名称及设备信息）
2. **Given** 选中某特征, **When** 重命名, **Then** 立即生效且重启后保持
3. **Given** 选中某特征, **When** 删除, **Then** 列表移除且此后不再参与认证

---

### Edge Cases

- 未插入指纹仪或 libfprint 不支持该 VID/PID
- 设备打开失败（枚举竞态、权限、被占用）
- 热插拔：插入后应能创建设备；拔出后进行中操作应可取消/结束
- 录入与识别并发：设备忙拒绝
- 录入中服务异常或面板断连：终止且不残留半成品
- 未录入任何指纹时发起识别：不匹配/失败提示
- 重复录入同一手指（当前用户）：拒绝
- 可切换模式下空特征库：识别失败
- 同一手指多用户模板：可切换时优先当前输入用户，再全库；不可切换时仅当前用户白名单
- 每账户特征达 10 个后再录入：拒绝

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 指纹采集、录入与比对必须在本机完成，依赖本机指纹仪与本地特征库，不依赖远端比对服务
- **FR-002**: 认证服务必须通过既有设备接口向控制面板提供录入启动/停止能力，录入过程持续上报进度、状态与结果（成功时返回特征数据供 daemon 落库）
- **FR-003**: 录入成功的指纹特征必须持久化在本机 FeatureDB，服务重启后仍可查询并参与认证
- **FR-004**: 认证服务必须提供特征查询接口，返回当前用户已录入指纹列表（特征 ID、名称等）
- **FR-005**: 认证服务必须提供特征重命名与删除接口，操作即时生效并持久化
- **FR-006**: 认证服务必须提供识别接口；一次扫描结束后返回匹配、不匹配或失败及可读原因；匹配成功时应尽快结束（不必等待抬起手指）
- **FR-007**: 设备处于录入/识别进行中时，新请求必须被明确拒绝并提示「设备忙」
- **FR-008**: 识别/录入停止请求发出后，进行中结果必须丢弃，不得误报成功
- **FR-009**: 质量不佳、取消、打开失败、无特征等场景必须给出明确可读提示
- **FR-010**: 录入前必须对当前用户已有特征做重复检测；命中则拒绝并提示「该指纹已录入」
- **FR-011**: 不可切换用户时，识别仅比对 daemon 注入的目标用户 `feature_ids`
- **FR-012**: 可切换用户时，daemon 下发空 `feature_ids` 并附带 `user_name`；设备须将该用户特征置于比对列表前端，再追加全库其余特征；命中特征 ID 由 daemon `matchUser` 反查用户并校验合法性
- **FR-013**: 设备装载基于 USB VID/PID（libfprint 支持列表/hwdb）；热插时创建并打开设备，拔出时卸载
- **FR-014**: 每个操作系统账户最多可录入 10 个指纹特征（与现有 daemon 上限一致）；达上限须拒绝并提示
- **FR-015**: 缺 libfprint 依赖时构建可跳过指纹驱动插件，不得导致核心组件无法编译
- **FR-016**: 特征 ID 由特征数据内容唯一确定（MD5），供查重与管理
- **FR-017**: 控制面板指纹页复用既有录入进度展示（阶段进度图 + 文案），不要求摄像头预览

### Key Entities *(include if feature involves data)*

- **指纹特征 (Fingerprint Feature)**: 一次成功录入的指纹模板；关键属性：特征 ID（特征数据 MD5）、iid、名称、所属用户、特征数据（libfprint 序列化打印）、关联 VID/PID/设备类型
- **指纹设备 (Fingerprint Device)**: 绑定具体 USB 指纹仪的设备对象；关键属性：设备 ID、VID/PID、状态（空闲/录入中/识别中）、驱动句柄
- **指纹驱动 (Fingerprint Driver)**: libfprint 插件实现；负责枚举支持列表、打开/关闭、阻塞式录入/识别、取消
- **认证请求 (Auth Request)**: 一次认证会话；含发起用户、是否可切换用户、认证方式、feature_ids / user_name、结果

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 指纹识别不得阻塞现有 PAM 认证链路：识别中可切换其他方式或停止，响应与现有体验一致
- **SC-002**: 本人已录入手指连续 20 次识别，通过不少于 19 次（≥95%）
- **SC-003**: 未录入手指/他人手指在不可切换场景下不得误通过当前用户认证（抽样交叉测试，误通过率目标与现网生物认证策略一致，交付时记录实测）
- **SC-004**: 正常条件下首次完整录入成功率不低于 90%（20 次中成功不少于 18 次）
- **SC-005**: 特征增删改查完成后即时生效，无需重启服务
- **SC-006**: 断网后录入、管理与识别全流程仍可用
- **SC-007**: 可切换用户场景下，用仅属于其他用户的手指可成功切换登录到该用户

## Assumptions

- 运行环境已安装可用的 libfprint（麒麟系多为 libfprint-2）及指纹仪硬件；设备须在 libfprint 官方支持列表内
- 控制面板指纹页（finger-page）既有流程可复用：点录入 → 密码验证 → 进度页按压；跨仓库仅需保证与本服务 EnrollStatus 语义兼容，本期不以摄像头预览为交付项
- 特征存储在本机受保护目录，仅认证相关进程经 FeatureDB/接口访问
- 认证场景沿用现有 PAM/会话链路，指纹为可选认证方式之一
- ZKTeco 等不在 libfprint 支持列表内的设备不在本需求范围，需独立驱动/SDK
- 本期不做独立活体/防伪算法层；依赖采集器与 libfprint 自身能力
